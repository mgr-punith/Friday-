# Orb reference research

The owner asked how these references create their animated orbs before choosing Friday's implementation.

| Reference | Actual rendering technique |
|---|---|
| [21st AI orb preview](https://cdn.21st.dev/konsstepnov/ai-orb/default/bundle.1792040465904-01d0b62e-6e9c-4dc9-af64-7bf40416ca20.html) | Canvas 2D draws procedural dots and lines in a `requestAnimationFrame` loop. The preview contains no video element; the movement is generated by code. |
| [LerSent001/orb](https://github.com/LerSent001/orb) | WebGPU renders WGSL shaders. Noise and layered sine waves create flowing curtain-like formations, with parameters for visual states and audio bands. |
| [weeeha/AI-Orb](https://github.com/weeeha/AI-Orb) | Raw WebGL draws one full-screen triangle through a procedural fragment shader. Its Aurora finish uses noise to warp a broad emissive band, a three-stop color ramp, and spherical coordinate compression for depth. No textures are fetched. |

## Friday's approach

Friday uses its existing native Kotlin `AssistantOrbView`. On API 33+ hardware canvases, an original AGSL shader combines spherical coordinate compression, one low-frequency smooth noise sample, and sine waves to bend a broad blue, cyan, and lilac band. A soft highlight and shading give depth while the circular silhouette stays stationary. This is a lightweight interpretation of the reference techniques, not a port of their shaders.

API 26–32, software canvases, and shader compilation failure use cached Canvas linear and radial gradients as a softer visual approximation. The renderer needs no images, WebView, bundled models, or new dependencies. The shader uses simpler noise than the references; reproducing their exact deformation would require a more detailed AGSL or native OpenGL ES implementation. The state, amplitude, and spectrum hooks remain available for future voice integration; the current home screen provides Idle and a simulated Preview while the microphone is off.
